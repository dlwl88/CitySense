# 基于 Spring Boot 与 Spring AI 的同城生活服务平台 — 前端

“基于 Spring Boot 与 Spring AI 的同城生活服务平台”的前端项目，使用 Vue 3、Vite、Element Plus、Axios 和 Pinia。

## 启动

```bash
npm install
npm run dev
```

默认访问地址：

```bash
http://localhost:5173
```

## 说明

- 开发模式通过 Vite 将 `/api` 请求转发到 `http://localhost:8083`，生产模式直接请求同源 Spring Boot 后端；登录、店铺、优惠券、支付和 AI 等功能调用真实接口。
- `src/mock/` 仍提供城市选项、展示资源以及部分菜品、评论和 AI 降级内容，完整业务操作需要后端及相关服务运行。
- 已包含首页、分类页、商家详情、个人中心、AI 美食助手

## 支付状态与超时关单

商家详情页支持普通券同步下单、秒杀券异步下单、查询订单状态和模拟支付。秒杀订单受理后由后端发送 15 分钟延迟关单消息，普通券当前不走该延迟链路。

后端的创建支付、支付回调和超时关单现已共用订单级 Redisson 锁，并通过数据库条件更新避免状态覆盖：支付先完成时保持“已支付”（状态 `2`），关单先完成时保持“已取消”（状态 `4`）并拒绝后续支付。关单失败由 MQ 重试，库存补偿按订单去重。

页面按真实订单状态显示“创建中”（`0`）、“待支付”（`1`）、“已支付”（`2`）、“已取消”（`4`）等，仅在已落库且状态为待支付时允许支付；支付、查询和下单处理中会禁用冲突按钮，避免重复提交。重新进入详情页时会刷新历史订单状态，个人中心也支持刷新并显示创建中状态。

模拟支付或生成支付链接前会重新查询 `/payment/status/{id}`，操作完成后再次同步后端状态。支付返回“订单处理中”、状态变化或请求超时时，页面会回查状态，更新本地订单记录，并提示当前已支付、已取消或仍在处理中；不会自动重复提交支付。若查询失败，显示“订单状态暂未确认”并禁用支付，用户可点击查状态恢复。支付请求成功但状态查询失败时，会单独提示请求已成功，避免误报支付失败。

订单的最终状态以后端查询结果为准。支付链接与回调均用于模拟流程，未接真实支付渠道。

后端锁、事务和补偿流程见 [项目说明](../PROJECT_DOCUMENTATION.md#45-模拟支付与超时关单)。
